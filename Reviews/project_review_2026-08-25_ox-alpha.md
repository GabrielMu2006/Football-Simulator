## 一、项目概览

一个本地运行的足球联赛模拟游戏，"旁观式管理后台"玩法：创建存档 → 初始化 40 支球队与 200 名真实球员池 → 按周推进赛季 → 查看联赛、杯赛、交易、选秀、荣誉与球员历史。

| 维度 | 现状 |
|---|---|
| 语言/技术栈 | Python 3.9+，PySide6 (UI v2)、Rich (TUI)、Tkinter (旧 GUI) |
| 核心代码量 | 约 8000 行（`football_simulator/` 包 + 4 个入口） |
| 前端数量 | 4 个入口：ui_v2_main（现役）、terminal_main、mac_app/gui_app（Tkinter，已过期）、main.py（argparse CLI，已过期） |
| 持久化 | 每存档一份 `state.json` + `config.json`，整文件覆写 |
| 测试 | **零测试**（无 pytest/unittest/CI） |
| 打包 | PyInstaller，macOS .app / Windows .exe |

## 四、问题清单（按优先级）

### P0 —— 数据安全

1. **非原子写盘 × 单副本 × 高频覆写**：`state.json` 用 `write_text` 直接覆盖原文件，无 temp+`os.replace`、无备份轮换。实测主存档已达 **9.26 MB**（历史赛季把 52 周比赛全量塞进 `history[]` 且 indent=2 美化输出，体积随赛季线性膨胀）。进程写入中途被杀 = 数月进度归零。
2. **无任何并发保护**：CLI 与 GUI 共享同一批写函数，两个进程同时模拟一周会互相整份覆盖，静默丢失进度。读-改-写窗口覆盖整个模拟计算期。

### P1 —— 正确性

3. **main.py 三处确定性 bug**：字段名错误、kind 枚举不匹配、ID 键不一致——旧前端渲染结果直接错误。
4. **旧前端语义全面过期**：gui_app/main.py 依赖的兼容别名属性早已失真——杯赛周显示"本周没有比赛"、已赛轮次恒为 0/38、休赛期判断永假。四个前端只有 ui_v2 在维护，其余靠别名"续命"却输出错误信息。
5. **赛季中途重新初始化会静默清空进度**：只拦截三类待办状态，赛季进行中误触即归零当前赛季，无确认防护。
6. **杯赛小组排名非确定性展示**：同分裁决每次查看现场随机洗牌，刷新两次小组榜可能变化，与当时出线事实矛盾；UI 还跨层调用了引擎私有函数。
7. **Windows 构建断链**：Windows.spec 的 datas 引用根目录不存在的 `football_simulator_config.json`，干净检出后构建直接失败。
8. **终端入口按 README 流程无法运行**：interactive_cli.py 依赖 rich，requirements-ui-v2.txt 却未声明。

### P2 —— 结构债

9. **上帝模块**：state.py 3941 行，承担序列化、赛季推进、三线杯赛、交易、选秀、荣誉结算、迁移修复等所有职责。
10. **快照全量重放**：读取路径从种子重放整个历史来重建内存状态，性能随赛季数恶化，且读路径带副作用（写缓存、写 current_save.txt）。
11. **领域规则 UI 复刻**：赛程预览、选秀顺位、档案合并、杯赛积分表在页面里重新实现一遍——规则改动需双处同步，必然漂移。
12. **中文串当状态机与持久化键**："冠军/亚军/四强""玩家通过/系统拒绝"既是显示文本又是荣誉积分表的匹配键；改一个词 = 旧存档荣誉失效。应区分机器枚举与 i18n 标签。
13. **魔法数字泛滥**：评分公式基线、身价指数 2.05、巨星线 74、点球种子胜率 0.6……数十个决定游戏平衡的系数全部内联无名。
14. **随机性不可复现**：全程 `SystemRandom()` 无种子注入点，无法复现任意比赛、无法做回归测试。
15. **异常处理缺陷**：裸吞 `except Exception: pass`；反序列化无 schema 校验，坏档抛 KeyError 直接崩程序。
16. **全部重活跑 UI 线程**：模拟周、审核、多存档扫描（每个存档完整反序列化 state.json）均同步执行，存档多时列表明显卡顿。

### P3 —— 杂项

17. 死代码：season.py（71 行整赛季模拟器）、placeholder_page.py 零引用。
18. 构建：`arch -arm64` 硬编码（Intel Mac 不可构建）；三个 spec 硬编码本机绝对路径 pathex；`upx=True` 可能压坏 Qt 动态库；pyinstaller 无版本上界、无锁文件；仅 ad-hoc 签名无公证。
19. 仓库卫生：release/ 目录 300+ 二进制框架文件入库，README 还建议继续提交二进制；`.DS_Store` 多处残留。
20. README 漂移：Python 3.9+ 口径存疑、项目结构图缺三个旧入口的废弃说明。

## 六、改进路线图建议

- 写盘改为 temp 文件 + `os.replace` 原子替换；

**第二步：止血正确性**

- 杯赛小组同分裁决改为确定性规则（如抽签结果落盘一次后复用）。

**第三步：补最小测试网**
- 优先覆盖纯函数：评分/身价公式、排名链、两回合晋级判定、阵容校验、round-robin 赛程；
- 加一条 CLI 冒烟测试：新档 → 模拟 3 周 → 重启加载一致。

**第四步：偿还结构债（长期）**
- state.json 瘦身：历史比赛移出主档或压缩存储；
- 快照重建改增量更新或落盘缓存；
- 中文状态串改机器枚举 + 渲染层映射；
- 魔法数字收敛为具名配置常量；
- 引入 ruff + mypy + pytest + GitHub Actions。

## 七、结语

以个人项目的标准看，Football Simulator 的**产品想象力和规则还原度令人印象深刻**——52 周赛历、三线杯赛、升降附加赛、转会审批、选秀池、荣誉体系环环相扣，README 的发布指引也写得像模像样。UI v2 的组件纪律和文案质感超出典型业余水准。

但它正站在一个临界点上：所有状态押注在一个 9MB 的非原子 JSON 上，所有逻辑挤在一个 4000 行的状态机里，而底下没有一张测试网。**当前最理性的投入不是继续堆功能，而是花一两天做持久化加固和冒烟测试**——这两件事做完，这个项目才真正具备"可以放心玩很多个赛季"的品质。
