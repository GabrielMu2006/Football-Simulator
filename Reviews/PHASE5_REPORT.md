## 4. 崩溃问题的完整定论（本轮用户可见的反复弹窗）

三段递进修复，全部有实证：
1. delegate 无 parent 无引用 → GC 提前删除 → 视图悬空指针（阶段 4 末已修：挂 parent+持引用）；
2. delegate 挂 view 为 parent 后，“提前清空/重建引用列表”的页面（赛事签表重建、比赛详情刷新）
   会让 shiboken 在引用消失时删除 C++ 对象，旧视图列映射悬空 → 崩溃（修正为 parent=view +
   **引用只增不清**，teams/matches 连续多轮稳定）；
3. 测试基础设施：“show 页面后允许 GC 回收”会触发 C++ 树级联析构重入 → 测试模块统一
   `_KEEP_ALIVE` 进程级持有页面实例（与生产 MainWindow 持有方式一致）。
最终：全部页面模块连续多轮运行稳定，全量套件零段错误。
